**同じ絵を何度読んでも、探して復号するのは一度だけになりました。** これまでは `loadImage` を呼ぶたびに資材を探し (包みの中まで走査する) デコードし直していたので、`draw()` の中で絵を読む書き方は毎フレームその費用を払っていました。手元の計測では、1 フレームの CPU 時間が 256 画素四方で 1.03 ms → 0.20 ms、1024 画素四方で 7.86 ms → 1.01 ms になりました。

**書き味は変わりません。** 返ってくる絵は毎回新しいので、読んだ絵を `set` や `fill` で塗り替えても、次に読んだ絵はファイルの中身のままです。走らせたままファイルを差し替えれば、次の読み込みからそちらが出ます (更新時刻を見ています)。待たない `requestImage` も同じ控えを使い、当たったときは別の仕事を起こしません。

控えは絵ごとではなく**画素の総量**で上限を持ち、超えたら古い順に捨てます。名前を組み立てて連番のコマを読むような書き方でも、際限なく増えることはありません。
