**`mokume watch` のプレビューで走るスケッチも、フレームごとに GPU の完了を待たなくなりました。** 窓を持って走らせるときは既に待っていませんでしたが、プレビューへ絵を渡す経路だけが毎フレーム GPU の終わりを待っていたので、`draw()` の CPU 仕事が GPU と重なりませんでした。手元の計測 (1920×1080・60 Hz) では、1 フレームあたりに CPU が止まっている時間が、図形 4000 個の絵で 1.8 ms → 0.65 ms、画面を覆う半透明の円 400 個の絵で 15 ms → 0.4 ms に縮みました (GPU が 1 フレームに収まらない絵では変わりません)。

**その代わり、プレビューに出る絵は 1 リフレッシュ (60 Hz で約 17 ms) 遅れます。** 描いた絵を GPU が描き終えるのを待たずに次のフレームへ進み、描き終わったことを次のフレームで確かめてから差し出すためです。絵そのものは 1 画素も変わりません。
