同じフレームで先に図形を置いてから `createShape { }` の中で `background()` や `get()` を呼ぶと、`Range requires lowerBound <= upperBound` でプロセスごと落ちていたのを直しました。先に何も置いていなくても、組み立ての中で画素を読むと組み立てた図形がフレームへ描かれて形から抜けていましたが、それも起きなくなりました。

**組み立ての中の `background()` と画素の読み書きは、効かなくなります。** 1 度注意して何もしません。これまで先に何も置いていなければ通っていた `createShape { background(0); … }` も、面を塗らなくなります。`get()` は透明を返し、`set()` と `pixels` への書き込みは書かれず、`pixels` は読み込み直さずにいまの写しを返します。塗り直しと画素の読み書きは、組み立ての前か後で行ってください。同じフレームで先に置いた描き場所 (`createGraphics`) の画素も、読み込み直しが要るなら組み立ての中では同じ扱いになります。

組み立ての中で、同じフレームに置いた描き場所を描き換えたとき、`noiseSeed()`・`noiseDetail()` で揺らぎの設定を書き換えたとき、描き場所の `createShape { }` の中でその描き場所の `endDraw()` を呼んだときも、同じように落ちていました。こちらは落ちずに空の形を返し、1 度注意します。それまでに組み立てたぶんは、形にならずにそのフレームへ描かれます。どれも組み立ての前か後で行ってください。
