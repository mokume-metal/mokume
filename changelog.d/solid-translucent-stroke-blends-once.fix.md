半透明の線 (`stroke(255, 0, 0, 128)` など) や `blendMode(.add)` などの下地を読む混ぜ方で、奥行きを持つ形 (`vertex(x, y, z)`) や立体 (`box()`・`sphere()` ほか・読み込んだモデル) の線を引くと、折れ目・端・曲線の継ぎ目・稜の集まる点だけが濃くなっていたのを直しました。線を組む部品 (帯・角・端・継ぎ目の円板) を重ねたまま積んでいたためで、平面の線と同じく、先に置いた部品との重なりを画面の上で引いて積むようにしました。重なる所は手前の部品を残すので、塗りのある形でも線は欠けません。線の形は変わらず、塗る範囲は縁の画素が入れ替わる程度 (引いた切り口を単精度で求めるため) です。奥行きの違う稜が画面で交わる所や、平行投影で正面を向けた箱の前後の稜のように奥行きの離れた部品どうしは、これまでどおり別々の線と同じく重ねて混ぜます。`createShape` に記録した形も、半透明の線で記録したときと、`Placement(fill:)` で半透明の色を掛けて置いたときに同じく直ります。

描く画素で 1 画素より細い線 (被覆を下げて描く線) のうち CPU で組む線 (奥行きを持つ形の線・モデルや `strokeJoin(.miter)` 以外の立体の稜線など) は、不透明の色でも重なった所が濃くなっていたので、同じく引いて積みます。この線は絵が変わります。それ以外の不透明の線は今までどおり重ねたまま積むので、絵も時間も変わりません。

代償として、半透明の立体の線を組む CPU の時間が増えます (`sphere(150)` の稜線・太さ 2 で 1 フレーム 0.19 ms → 2.5 ms、`detail: 64` では 1.3 ms → 21 ms、`box(160)` で 0.010 ms → 0.061 ms)。画面で小さく写る細かい網に太い線を引くとき (`sphere(10, detail: 64)` に太さ 20 など) は、引く準備が大きくなりすぎるので引かずに重ねて積みます。`shader()` の断片が半透明を返す立体の線 ([#2184](https://github.com/mokume-metal/mokume/issues/2184)) と、GPU で広げる細い稜線 ([#2185](https://github.com/mokume-metal/mokume/issues/2185)) は、まだ重なった所が濃くなります。
