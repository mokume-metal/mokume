`loadModel` が OBJ の頂点 (`v`・`vn`・`vt`) の数を 10 進の綴りだけで読むようになった。16 進 (`v 0x10 0 0`) や、数字の後ろに NUL などが続く `vt` の 2 つ目 (`vt 0.5 1\0`・`vt 0.5 0x1`) を黙って数として置かず、読めない行として読み飛ばし、`Model.skippedLines` に数える。

これまでは `v 0x10 0 0` が x = 16 の頂点として置かれ、`vt` の読めない 2 つ目は書いていないものとして 0 で置かれていた。どちらも読み飛ばしに数えられないので、壊れたファイルに気付く手段が無かった。`v 1.5 -2 3e1`・`vt .5` のような 10 進の綴りの読み方は変わらない。
