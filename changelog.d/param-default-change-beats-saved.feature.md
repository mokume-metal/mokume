**`@Param` の既定値をコードで書き換えると、つまみで合わせた保存値より勝つようになりました。** これまでは、既定値を 80 から 60 に書き換えても、つまみで 120 に合わせた保存が黙って勝ち、触っていない値の既定値を書き換えても保存の古い値に凍っていました。いまは保存 (`.mokume/state/params.json`) が書いた時点の既定値を併記していて、起動時にコードの既定値と比べ、変わった値だけ保存を捨ててコードの既定値で始まります。

- 捨てたときは、名前・捨てた保存値・前の既定値・新しい既定値を挙げて標準エラーへ 1 度だけ言い、観測の最初の応答 (`.mokume/params/report.json`) の `discarded` に `reason: "defaultChanged"` で載せます (`discarded` の `reason` の列挙が 1 つ増えました。スキーマの版は動かしていません)
- 触っていない値の既定値を書き換えたとき (新しい既定値になります) と、合わせた値をそのままコードの既定値へ書き戻したとき (120 のまま) は、失うものが無いので黙ります
- コードを変えずに起動し直したときは、いままでどおり合わせた値が戻ります
- 既定値を併記する前の保存 (`defaults` の列が無い) は、いままでどおり名前と型で戻し、次に書くときに列を足します。新しい保存を古い版の mokume が読んでも、値はいままでどおり戻ります
- **代償**: 起動のたびに既定値が変わる宣言 (`@Param var seed = Double.random(in: 0...1)` など) は、保存が毎回捨てられて効かなくなります。合わせた値を残したい宣言は、既定値を固定して書きます
