`mokume watch` が走っている場所 (区画 `.mokume/viewport` が在る場所) で、見張りに起こされていない実行が見張りの窓と標準入力を奪わなくなった。直に走らせたスケッチと `mokume run` は自分の窓を開き、見張りの窓は見張っている作品の絵のまま変わらない。`mokume render` は標準入力が閉じていても (`< /dev/null`・CI・cron) 頼んだ枚数を書いて 0 で終わり、窓を持たない `SketchRuntime` は端末に `O_NONBLOCK` を残さない。区画が在るのに窓を開くときは、そのことを 1 度名乗る。

見張りは子を起こすとき、窓の持ち主であることを環境変数 `MOKUME_VIEWPORT_OWNER` で伝えるようになった (子は読んだら消すので、スケッチが起こすプロセスには継がれない)。これまでの見張りはこれを渡さないので、**`mokume` の道具 (CLI) とスケッチが固定しているライブラリの版を揃えてほしい**。

- 古い道具で新しいライブラリのスケッチを見張ると、子は見張りの窓へ差し出さずに自分の窓を開く (見張りの窓は空のまま)。見張りの窓で触った出来事は届かず、見張りが落ちても子は気付かない (自分の窓の × で止められる)。子は「見張りから起こしたなら道具とライブラリの版がずれている」と名乗る
- 新しい道具で古いライブラリのスケッチを見張る分には、これまでどおりに動く。ただし区画が残った場所で `mokume run` すると、古いライブラリは窓を開かず、ライブラリの側からは何も言わない。道具の `run` が区画の在処と版のずれの手掛かりを 1 行名乗るので、ライブラリを上げるか区画を消してほしい。`mokume render` は、古いライブラリでは閉じた標準入力で 0 枚のまま止まる形が残る
