`mokume run --record` の記録が、読んだローカルの資源 (画像・文字やデータ・SVG・モデル・フォント・音・`.metal` の断片) の中身のハッシュを持つようになり、`mokume replay` で流したときに中身が違う資源を「再現を保証しない」と名前つきで名乗る。

記録した後に `dot.png` を描き直してから流すと、最後の 1 行と `report.json` の `unreproducible` に `dot.png` が載る。照合の一致 (`matched`) は絵だけで決まり、資源の違いだけでは変わらない。記録の途中で同じ名前の中身が変わったときは、記録の側が名乗る。文字・データ・表・JSON・XML・SVG・OBJ・`.metal` の断片は読み手が使ったバイト列そのもののハッシュで、画像・STL・フォント・音は OS がファイルの場所から読むため、読んだ直後にファイルをもう 1 度読んで取る (その間に書き換わると、使った中身とハッシュが食い違いうる)。読めたのにもう 1 度読めなかった (消えた・開けなくなった) ファイルは、欄に載せず「再現を保証しない」と名乗る。ハッシュを取るのは記録か再生をしている実行だけで、ふだんの実行の読み込みは遅くならない。URL から読んだ本文・カメラ・動画は対象外 (これまでどおり別の理由で名乗る)。載るのは mokume の読み込みの API が読んだファイルだけで、`assetURL` が返した場所からスケッチが自分で読んだものは載らない。走らせたまま差し替えた `.metal` の断片は、これまでどおり「差し替えた断片」の理由で名乗る。名前はスケッチが渡したとおりに載る (絶対パスで読めば絶対パス)。この欄を持たない前の記録も、そのまま流せる。
