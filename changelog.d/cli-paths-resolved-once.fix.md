`mokume run ../sketch` のように `..` で始まる場所を渡したとき、場所を取り違えて起動に失敗していた (`..` だけ・`../..` では実行した場所で動いていた) 問題を直しました。`run` / `watch` / `render` / `doctor` / `bundle` に渡した場所 (`bundle --out` も) は、実行した場所から一度だけ絶対パスに解いてから使います。

`MOKUME_WORK_DIR` に相対パスを与えてスケッチの外から `run` / `watch` / `render` を実行したとき、道具とスケッチが別々の場所を区画の基準にしていた (道具は実行した場所から、スケッチは自分の場所から解いていた) 問題を直しました。スケッチへは道具が解いた絶対パスを渡すので、観測・入力・つまみが同じ区画で噛み合います。

`mokume new` と `mokume bundle` が最後に出す案内を、実行した場所からそのまま貼って動く形にしました。`new --path` で別の場所に作ったときも、`cd` の行が作った場所を引用付きの絶対パスで指します (これまでは `cd <名前>` で、`--path` を付けると入れませんでした)。`bundle <スケッチ>` の「配布前の確かめ方」の行も、スケッチの `.build` と `.app` を絶対パスで指すので、スケッチの外で実行しても `.build` を退避して確かめられます。

`mokume new --local <場所>` で、場所の末尾が `..` や `.` のときに作ったスケッチが依存を解決できなかった問題を直しました。依存の名前を、Swift Package Manager と同じ規則で、作られるスケッチの実際の場所 (シンボリックリンクを解いた場所) から解くようにしています。場所の末尾が `.git` のときも、Swift Package Manager と同じくそれを落とした名前を使います。あわせて、`"` や `\` を含む場所を渡しても `Package.swift` が壊れないよう、Swift の文字列として書き込むようにしました。
