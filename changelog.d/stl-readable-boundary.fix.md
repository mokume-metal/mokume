**`loadModel` / `requestModel` が、STL を読めるか読めないかの境目を、説明に書いたとおりに守るようになった。** 読み手の Model I/O の判定にそのまま従っていたため、次の 3 つが破れていた。

- 128 バイトに満たない文字の STL は、面があって形が整っていても、読めないとして投げていた。字下げせずに手で書いた 1 面だけの STL (100 バイト前後) が当たる。大きさによらず読めるようにした。
- 前に空白のある文字の STL・大文字の `SOLID` で始まるもの・STL でない文字のファイルは、投げるはずのところ、84 バイト目が改行・タブのときに限ってバイナリとして読まれ、座標が 1e34 級のでたらめな形が返っていた。説明どおり読めないとして投げるようにした。同じ道で、84 バイト目が改行になる面の無い STL (1 行目がちょうど 83 文字のものなど) も、空のモデルではなくでたらめな形になっていたのを直した。
- 改行が CR だけの STL のように、読み手が読めない文字の STL が、面を書いていても空のモデルとして読めてしまうことがあった (128 バイト以上のもの。128 バイトに満たないものは投げていた)。空のモデルは「読めたが面が無い」ときだけにして、読めないものは投げるようにした。

バイナリの STL・見出しが `solid` で始まるバイナリ・途中で切れたバイナリ (揃っている面だけを読む)・面の無い STL (空のモデル)・大文字の `SOLID` や STL でない文字 (読めないとして投げる) の結果は変わらない。
