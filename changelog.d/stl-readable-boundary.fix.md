**`loadModel` / `requestModel` が、STL を読めるか読めないかの境目を、説明に書いたとおりに守るようになった。** 読み手の Model I/O の判定にそのまま従っていたため、次が破れていた。

- 128 バイトに満たない文字の STL は、面があって形が整っていても、読めないとして投げていた。字下げせずに手で書いた 1 面だけの STL (100 バイト前後) が当たる。名前に制御文字 (FF・VT・NUL・DEL・ESC) を含む小さい STL も同じだった。大きさによらず読めるようにした。
- 前に空白のある文字の STL・大文字の `SOLID` で始まるもの・STL でない文字のファイルは、投げるはずのところ、84 バイト目が改行・タブのときに限ってバイナリとして読まれ、座標が 1e34 級のでたらめな形が返っていた。頭に制御文字 (FF・VT・DEL・ESC など) があるだけでも同じだった。説明どおり読めないとして投げるようにした。
- `solid` で始まる文字の STL でも、読み手が面を読めないと、同じ道でバイナリとして読み直されて、でたらめな形が返っていた。面の無い STL (84 バイト目が改行になるもの) が空のモデルにならない、`facet` の行に `normal` が無い・大文字の `FACET NORMAL`・`facet` の行が無い、が当たる。頂点が 3 つでない面があると隣の面の頂点を食って壊れた形が返るのも、同じ根である。読み直される余地を残さず、書かれた面の数と組み立てを確かめて、合わなければ読めないとして投げるようにした。
- 改行が CR だけの STL のように、読み手が読めない文字の STL が、面を書いていても空のモデルとして読めてしまうことがあった (128 バイト以上のもの)。空のモデルは「読めたが面が無い」ときだけにして、読めないものは投げるようにした。

バイナリの STL・見出しが `solid` で始まるバイナリ・途中で切れたバイナリ (揃っている面だけを読む)・面の無い STL (空のモデル。名前に FF・VT や UTF-8 でない字があっても) の結果は変わらない。**次は、これまで読めた (または空になった) ものが、読めないとして投げるようになる**: 前に空白やタブのある、面の無い solid・頂点の無い面だけの STL (頂点の無い面と正しい面が混ざったものも)・頂点が 3 つでない面を含む STL・改行が CR だけの STL・面の数が 2^24 (約 1,677 万面・800 MB を超える) 以上と宣言して大きさが合わない (切れた) バイナリ・UTF-16 で書き出された文字の STL (BOM あり・なし。これまでは、でたらめな三角形が返っていた)。大きさが 84 + 50 × 面の数と合う完全な大きいバイナリは、これまでどおり読める。
