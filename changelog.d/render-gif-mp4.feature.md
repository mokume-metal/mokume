**`mokume render --out loop.gif` と `--out loop.mp4` で、貼ったり送ったりする形へ直接書き出せるようになりました** ([#2440](https://github.com/mokume-metal/mokume/issues/2440))。これまでは `.mov` (ProRes 4444) か連番しか書けず、授業の提出・SNS・README へ貼るたびに外の変換ツール (ffmpeg など) が要りました。`mokume render --fps 25 --seconds 4 --out loop.gif` と打つと、100 枚・各枚の遅延 4/100 秒・繰り返し無限の GIF が、窓を開かずにできます。4 秒で 1 周する作品なら継ぎ目なしのループです。`.mp4` は H.264 の MP4 で、枚数と刻みは `.mov` と同じく `--fps` と `--seconds` のとおりです。外の道具は要りません (MP4 は AVFoundation、GIF は ImageIO で書きます)。

**配る形は、同じ引数から書いても画素が一致するとは約束しません** (減色や符号化は OS のもので、版で変わりえます)。書き終わりにもそう表示します。元にする形は今までどおり `.mov` か連番で、そちらの水準 3 は変わりません。GIF は 256 色で、色は sRGB に直して書き、透けた画素はアルファ 128 以上を不透明・それ未満を透明にします (半透明は書けません)。MP4 は透けを書かず、色は sRGB に直して書きます。

GIF の遅延は 1/100 秒の整数倍なので、`--fps` は 100 を割り切る値 (100・50・25・20・10 など) だけを受け付けます。`--fps 60` のように割り切れない値は、ビルドの前に使い方の誤りとして止まり、使える近い値 (50・100) を言います。黙って遅延を丸めることも、枚を間引くこともしません。100 fps の GIF は 1/100 秒の遅延を書きますが、この短さを長く見せる再生環境があるので、50 fps までを勧めます。作品の `beginRecord` は、これまでどおり `.mov` と連番だけを受けます。
