`mokume run --record take.json` と `mokume watch --record take.json` で、フレームの時計 (`clock: .frames`) のスケッチの実行を、最初のフレームから終わりまで 1 本のファイルに記録できるようになりました。毎回の入力 (キー・マウス)・外から書いたつまみの値・時刻を指定した観測・開始の状態 (乱数の種・つまみの値・作者の時計の秒) に加えて、毎フレームの `expose` の値と、60 フレームごと + 最後の 1 枚の画素のハッシュが残ります。記録の形式は `Schemas/replay-record.schema.json` です。

行き先は `--record` が必ず指します (既定の行き先はありません)。窓を閉じる・SIGTERM・Control + C のどれで終えても最後に描いた枚まで書いて閉じ、途中で落ちたときは `take.json.<プロセス番号>.partial` が残るだけで `take.json` は作られません (完成として読まれません。`setup()` が投げて終わった実行も同じです)。`watch` は作り直すたびに新しい記録を始め、`take-1.json`・`take-2.json` のように世代ごとに別のファイルへ書きます。始めるときに前の見張りの同じ並びのファイルは消します。同じ行き先へ書く実行が 2 つあるときは、あとから始めた実行が記録を始めず理由を言います。前の回の完成品は、実時間の時計で記録を始めない回も含めて、始めるときに消します。実時間の時計のスケッチには記録を始めず、理由を言って走り続けます。

ゲームパッド・MIDI・OSC / TCP / UDP / WebSocket・シリアル・マイク・カメラ・動画の値、ドロップした / 選んだファイルの中身、URL から読んだ本文、窓で実時間に鳴る音の解析値は記録に載りません。使った作品の記録は、それを `unreproducible` に名乗ります。窓で録った記録には `"window": true` が付き、拡大した字の焼きを次のフレームへ送る窓の最適化は、記録している間は切ります (窓なしで流す側と同じ手順で描くため)。記録を流して照合する `mokume replay` は次の段で入ります。
