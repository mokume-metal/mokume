名前から作るファイルの名前が長すぎるとき、`mokume new`・`mokume render --out`・`beginRecord()`・`save()` が、作る前に長さと使える長さを名指して断るようになりました。これまでは、`mokume new` が、250 字以上の名前では `Package.swift` と空のディレクトリだけを残して止まり、それより短い長い名前でも `Created` と言ったのに `swift build` が `File name too long` などで組めませんでした。`render --out` は、スケッチを組んだ後に子の中で落ちていました。

線は、いま失敗する名前のちょうど手前に引いています。`new` の名前は 118 まで (資材の包みが名前を 2 回含むファイル名を作るため。`が` のような分解で 2 と数える字は 59 字)、PNG の連番と `save()` のファイル名は 247 まで、`.mov` は 255 までです。長さは、ファイルシステムが数える形 (濁点の付いた仮名や `é` は 2) で数えます。連番は番号が桁に収まらなくなると名前が伸びるので、`render` は `--fps × --seconds` から分かる最後の枚の名前で見ます。`beginRecord()` は枚数が先に分からないので、1 枚目の名前で見ます。作るディレクトリの名前も、1 つにつき 255 まで見ます。NUL や空の名前は、書けない名前として断ります。
