外から送る入力の線 (`input-request`・標準入力の 1 行) の整数の欄 (`button`・`code`・`clickCount`・`serial`) と、つまみの `int` の値 (`params-request`・保存したつまみの値) が、桁の多い端数つきの数を断らずに整数として読んでいたのを直しました。`1.00000000000000000000001` や `0.99999999999999999999999` は 1 に、`12345678901234567.5` は端数を捨てた 12345678901234567 になっていました。いまは `2.5` と同じく整数でない値として扱い、入力はその 1 件を `ignored` に数え、つまみは `typeMismatch` で名指して捨てます。プレビューのつまみが作品の応答から読む宣言の `int` の値も同じで、その 1 件だけを飛ばして名乗ります。共有する画面の目録 (`viewport-surface`)・名乗った送り手の一覧 (`frame-listing`)・区画に残っていたつまみの応答の番号 (`revision`)・作り直しをまたぐ時計の引き継ぎ・MCP の `api_details` が読む詳細の版の整数の欄も同じ読み方にしました。`3.0`・`1e3` のような整数の綴りと、範囲の外の整数の扱いは今までどおりです。プレビューのつまみが宣言を飛ばしたときと、時計の引き継ぎが使えなかったときの知らせは、`2.5` でも `DecodingError: Number 2.5 is not a whole number (at params[1].value)` のように値と場所を言う文面に変わります。
