**フレームの描き切りが GPU の完了を待たなくなりました。** これまでは 1 フレームごとに CPU が GPU の終わりを待っていたので、`draw()` の中の仕事 (図形の組み立て) と GPU の描画が交互にしか走りませんでした。待ちを「次に GPU の結果や置き場へ触る直前」へ動かしたので、`draw()` の CPU 仕事が前のフレームの GPU と重なります。手元の計測では、図形 4000 個 + 効果 2 段の絵で 1 フレームの CPU 時間が 17.5 ms → 12.7 ms に縮みました (GPU だけが重い絵では変わりません)。

**書き味は変わりません。** 画素を読む口 (`pixels` / `get` / `loadPixels()`)・計算の結果を読む口 (`read`)・数の並びや粒や画像へ書く口は、それぞれ触る直前に自分で待つので、これまでどおりそのフレームの正しい値が読め、書いたものは次の描き切りから効きます。それらを使わないスケッチは 1 度も待ちません。

**1 つだけ守ること。** `pixels` は描画先そのものへの窓なので、取ったフレームの中で使い切ってください。プロパティに取っておいて次のフレームで書くと、GPU が描いている途中の面へ触ることになります。
