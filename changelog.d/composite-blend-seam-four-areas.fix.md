`blendMode(.lightest)` など下地を読む混ぜ方のうち、`.lightest` / `.screen` / `.darkest` / `.multiply` / `.difference` / `.exclusion` で、塗りと輪郭を両方持つ `rect` / `square` / `ellipse` / `circle` / `arc` を描くと、塗りと輪郭が接する継ぎ目で下地が透けていたのを直しました。`createShape` で記録したこれらの形を `shape()` で置いたときも同じです。黒地に白い塗りと白い輪郭の円を `.lightest` で描くと、太さ 1 の輪郭の内側に、最大 24% 暗い画素が輪になって出ていました (白地に黒の `.darkest` / `.multiply` では明るい輪)。いまは `.blend` と同じく、画素の中の塗りだけ・塗りと輪郭の重なり・輪郭だけの所をそれぞれ混ぜた色を面積の比で足すので、継ぎ目に下地が混ざりません ([#1818](https://github.com/mokume-metal/mokume/issues/1818))。

そのどれかに丸ごと入る画素は、これまでどおり塗りだけの形と輪郭だけの形をこの順に描いた絵と同じです。縁と継ぎ目の画素だけが、分けて描いた絵と違う色になります。**`.difference` / `.exclusion` で、塗りと輪郭が重なる所が打ち消し合うのはこれまでどおりです。** 黒地に白い塗りと白い輪郭の円を `.difference` で描くと、輪郭の帯の内側半分 (塗りと帯が重なる所) は、塗りの白の上で輪郭の白と差を取るので黒 (|1 − 1| = 0) になります。分けて描いた絵と同じで、直ったのは塗りと帯が接する継ぎ目の漏れです。

`.add` / `.subtract` は不透明な地の上では見た目が変わりません。透けた地 (`createGraphics` の透明な所など) では、継ぎ目の画素が塗りと輪郭の面積どおりになります — `.add` は不透明度だけが変わり、`.subtract` は色と不透明度の両方が変わります。たとえば透明な地で、不透明な塗りと輪郭が半分ずつ掛かる継ぎ目の画素は、`.subtract` でこれまで塗りの色の半分・不透明度 0.75 だったのが、塗りと輪郭の色の半分ずつ・不透明度 1 になります。`.blend` と `.replace` の絵、塗りだけ・輪郭だけの形の絵は変わりません。
