# 描画に影響する変更が置かれる場所。ここに触れた PR は「絵が動きうる」ものとして扱う。
#
# 用途は 2 つで、**一覧の実体はこの 1 つ**に保つ (ADR-0001 原則 9)。
# 読む側の照合も 1 つで、scripts/drawing-paths.sh の touches_drawing がそれにあたる:
#
#   evidence  絵の証跡を要求するかの判定 (#306) — scripts/check-drawing-evidence.sh
#   coverage  手元の実行の報告 (local-render) を代理で済ませてよいか (#435) と、
#             描画 PR の順番待ちに入るか (#467) の判定 — scripts/render-status.sh
#
# 行は「先頭一致するパスの前置き」を 1 つ書いた形で、どの行も両方の用途に効く。
# # で始まる行と空行は無視する。読むのは行の先頭の語だけで、空白の後ろは読まない
# (書いても効かない)。
#
# 以前は前置きの後ろに印を続けられた。`evidence-only` (証跡は要求するが、手元の実行の
# 覆いには数えない。#497) が 2 つの用途の答えを分けていたが、最後に付いていた Sketches/
# から #1377 で外れ、読む口ごと #1428 で畳んだ。
#
# 迷ったら**広く**取る — 狭すぎたときの代償が、絵の退行が誰にも見られずに main へ入る
# ことだからである。
#
# 広すぎたときの代償は 2 つある。手元で make ci-check を打つことと、**絵の変わらない PR に
# no-visual-change を付けること**である。後者を数えないと、逃がしラベルで外す癖がついて
# 機構ごと形骸化する (scripts/check-drawing-evidence.sh の冒頭が言うところ)。
#
# **例外の域を出ていないかは数えられる** (#711)。2026-09 時点で no-visual-change の付いた
# 30 本を分類したところ、26 本は描画の中核・台帳・参照スケッチに触れており、証跡の要求
# そのものが妥当だった。この一覧の広さ由来で不要に要求されたのは 4 本 (台帳を触らない
# テストコードの変更) である。
#
# **狭める提案は、この数字を動かしてから出す。** Tests/MokumeCoreTests/ を「台帳関連だけ
# evidence」に割れば 4 本は消えるが、LedgerDetectionTests.swift のような境界のファイルが
# あり、**どのテストが絵に影響するかを人が判定して書き続ける**ことになる — いまの「テストは
# 全部対象」が持つ、判定の要らなさを失う。coverage の側は今のままが正しい (テストコードが
# 変われば make ci-check の結果が変わる) ので、片側だけ割ると読み方も増える。
