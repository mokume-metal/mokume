# ADR-0017: エージェント支援の置き場 — リポジトリで完結させる

## 状態

採用 (2026-08-27)

## 文脈

[ADR-0001](0001-founding-principles.md) は、作品を作る人間と協働する AI エージェントの**両方を一級の開発者として想定する**と定めた。同原則 9 は「正典は GitHub に置き、変更は Issue から始める」「文書は『どれが正か』を常に 1 つに保ち、同じ内容の二重管理を作らない」と続く。

エージェントがこのリポジトリの作法どおりに動くとき、支えているのは 2 系統ある。

1. **リポジトリ同梱の機構** — `scripts/plan-record.sh` (着手時プランの投稿を強制)・`scripts/agent-comment-guard.sh` (コメントの署名)・`scripts/pr-identity-guard.sh` (PR の作成主体) を `.claude/settings.json` が配線している。CI の `review-gate` もここに属する
2. **個人環境の設定・プラグイン** — 各自の `~/.claude/` に入っているもの。汎用の作法 (プランの合意・CI の見届け・ブランチの掃除) を供給する

`.claude/settings.json` は 2 系統目のうち 1 つを**リポジトリ側から宣言していた** — `extraKnownMarketplaces` と `enabledPlugins` に個人のマーケットプレイスと `repo-standards` プラグインを書いており、これは「このリポジトリで作業する全員にそのプラグインが入る」ことを意味する。

この構成が実際に噛み合わなかった。[#159](https://github.com/mokume-metal/mokume/pull/159) で、プラグインの Stop フックが**承認待ちの赤に対して 3 回「CI を直せ」と鳴った**。`verify: human` の Issue に紐づく PR は Approve が付くまで `review-gate` が赤い ([ADR-0002](0002-issue-lifecycle-and-merge-approval.md) 決定 3) というのはこのリポジトリの設計であって、汎用の機構はそれを知らない。**正常な状態を異常と判定した**わけである。個々のフックの出来の問題ではない — リポジトリ固有の設計を、リポジトリの外にある機構が判定していることの帰結である。

一方でリポ側は、既に逆向きの解を持っていた。`.claude/settings.json` の `env` にある `CLAUDE_PLAN_RECORD: 0` は、個人環境にある同種のフックを**黙らせる**設定で、`scripts/tests/plan_record_test.py` の `SelfContainedTest` は「設定もスクリプトも `~/.claude` に手を伸ばさない」ことを検査している。**リポ側が担保して個人側を黙らせる**という向きが既に選ばれており、プラグインの宣言だけがその例外として残っていた。

## 決定

### 1. エージェント支援はリポジトリで完結させる

mokume 向けのエージェント支援 (スキル・hooks・設定) は `.claude/` に置き、個人環境のプラグインやマシン設定に依存しない。理由は二つ:

- **このリポジトリで作業する誰の環境でも同じ支援が効く。** 入れている人にだけ効く支援を前提にすると、規約が環境によって変わる
- **支援機構自体を Issue → PR の通常ループで育てられる。** 作法が合わなければ、このリポジトリの中で直せる

### 2. 個人環境のプラグインを宣言しない

`.claude/settings.json` に `extraKnownMarketplaces` / `enabledPlugins` を書かない。検査で固める (`SelfContainedTest`)。

**個人が自分の `~/.claude/` に何を入れるかは自由である。** 縛るのはリポジトリが**要求する**側だけで、各自の道具立てには踏み込まない。

### 3. 二重に動くときは、リポ側が担保して個人側を黙らせる

同種の機構がリポジトリ側と個人環境の双方にあるとき、**向きを固定する** — リポ側が支援を持ち、個人側は環境変数で黙らせる。前例は `CLAUDE_PLAN_RECORD: 0` である。

逆向き (個人側に任せてリポ側を薄くする) は採らない。個人環境の機構はリポジトリの設計を知らないため、`ci-watch-stop` の空振りのように**正常を異常と判定する**。判定の根拠を持っている側が判定する。

### 4. 支援は必要が示されてから足す

[ADR-0008](0008-mechanism-needs-demonstrated-harm.md) の順序をそのまま適用する。プラグインを外して届かなくなる支援 — 合意前の編集の deny・CI の見届け・ブランチと worktree の掃除・各種スキル — は、いずれも**現在の mokume の規約が要求していない**。強制していることはすべてリポ同梱のフック 3 本と CI が担っている。

必要が示された時点で `.claude/skills/` へ自前で置く。

## 影響

- `.claude/settings.json` から `extraKnownMarketplaces` と `enabledPlugins` を削除する。AGENTS.md の「エージェント環境の設定」は本 ADR へ接続し、「例外は汎用の個人標準のみ」という但し書きを畳む
- **個人環境で汎用プラグインを使い続けることは妨げない。** mokume がそれを要求しなくなるだけで、各自の環境では従来どおり効く
- 決定 3 は、リポ側の支援が増えるたびに「個人側を黙らせる env」を足す可能性を意味する。写しが増えるのではなく、**向きの宣言**が増える
- 本 ADR は置き場を決めるもので、[ADR-0003](0003-agent-identity-separation.md) (エージェントの identity) と ADR-0008 (機構を足す基準) とは軸が異なる。三つは重ならない — 誰として行うか / 何を足してよいか / どこに置くか
