# ADR の書き方

ADR を書く・直すときの規約。ルートの `AGENTS.md` の続きで、ここに無いことはそちらに従う。

## 何を ADR にするか

ADR にするのは、後から「なぜそうしなかったか」を引く必要がある決定である。退けた案と代償があり、同じ案がまた出たときに理由ごと答えたいものを指す。手段の細部・一度きりの判断・作業の経過は Issue に置き、機構の内部はスクリプトの冒頭に置く。迷ったら Issue に置き、同じ案が 2 度目に出たときに ADR へ上げる。既存の ADR には遡って適用しない ([#2081](https://github.com/mokume-metal/mokume/issues/2081))。

退けた案は決定節に理由ごと書く (下の「現行の決定から読めるようにする」)。引くときは語で探す。改訂が重なって軽くした ADR の当初の決定と置き換わった決定は `docs/decisions/history/` にあるので、そこも引く:

```bash
grep -n -E '採らな|見送|退け|当初の決定|却下' docs/decisions/0*.md docs/decisions/history/*.md
```

## 形

- 節は 状態 / 文脈 / 決定 / 影響 の 4 つ。他の文書を読まなくても分かるよう、自己完結で書く
- 他の ADR は `ADR-00NN` の綴りで参照する
- 帰属は ADR 自身の先頭に SPDX ヘッダ (HTML コメント) を置いて宣言する。番号付きの ADR は `REUSE.toml` に足さない

```markdown
<!--
SPDX-FileCopyrightText: 2026 mokume-metal
SPDX-License-Identifier: MIT
-->
```

## 現行の決定から読めるようにする

改訂が重なった ADR は、決定節で現行の選択を先に、捨てた選択と理由を後に置く。
置換済みの決定は置換先へ案内する。長い場合は同じ本文内への案内を置いてよいが、
別の要約を正典として維持しない。4節と決定番号を保ち、既存の見出しへの参照も残す。

文脈の当時の問題と、影響の現在の制約を区別する。「採用」は全実装の完了を意味しない。
未決や未実装は明示して Issue へ結び、進捗台帳を ADR に複製しない。全面移行はせず、
改訂する文書から適用する。

## 改訂が重なった ADR を軽くする

日付入りの改訂・追補の見出しが本文に **5 つを超えた** ADR は、番号と決定の番号を変えずに軽くする。改訂が重なった ADR は 1 本で 2〜3 万字になり、決定を変えるときと退けた案の理由を引くときに、1 本を丸ごと読む重さが残るためである ([#2140](https://github.com/mokume-metal/mokume/issues/2140))。`make adrs` が 6 つ目で赤くして、この手順を案内する。

数えるのは見出しの数である。「改訂」か「追補」と日付を両方持つ `##`〜`####` の行を 1 つと数え、日付が前でも後ろでもよい。日付の種類の数ではないので、同じ日の 3 つの改訂は 3 つになる。副題だけの小見出しは数えない。5 つまでは通る。

| 置き場 | 置くもの |
| --- | --- |
| 本文 `docs/decisions/<番号>-<名前>.md` | 状態・文脈・現行の決定・その決定で退けた案・影響 |
| 経緯 `docs/decisions/history/<番号>.md` | 当初の決定と改訂の理由・改訂の見出しの本文・置き換わった決定 |

経緯の置き場が `docs/decisions/` の直下でないのは、番号付きの ADR として数えられないようにするためである (`make adrs` は直下の `NNNN-*.md` だけを数え、`history/` は見ない。連番の一意性にも掛からない)。

1. **番号・決定の番号・決定の見出しは変えない。** 「ADR-00NN 決定 N」の参照がそのまま効く
2. **決定の中身は本文に残す。** 経緯へ移すのは、見出し・当初の決定・改訂の理由・置き換わった決定である。現行の決定の足し込みになっている段落を経緯へ移すなら、本文に書き起こした要約を置かない (別の要約を正典として維持しない)
3. **経緯ファイルを作る。** 先頭に SPDX ヘッダ (「形」の例と同じ) を置き、本文へのリンクと、決定の番号ごとの節 (`### N. 決定の見出し`) に、移した見出しを**元の綴りの日付入りのまま**置く。採択時の全文を引く `git show <commit>:<パス>` を 1 行書く。書式の小さな例は `history/0031.md`。経緯ファイルが既にあれば、末尾へ足す
4. **本文の「## 状態」の下に案内を 1 行置く**: `改訂の経緯 (当初の決定・各改訂の理由・置き換わった決定) は [history/<番号>.md](history/<番号>.md) にある。`
5. **状態欄は触らない。** 印 `改訂あり (本文の「改訂 (日付)」見出し)` と凍結した ` / 改訂 (日付)` の並びを残す。印は「改訂がある」ことだけを示し、見出しが本文と経緯のどちらにあるかは言わない。綴りを変えると並んだ PR が衝突する (下の「改訂の書き方」)。軽くした本文には日付入りの見出しが無い (経緯ファイルにある) ので、改訂の一覧は両方を引く
6. 軽くした後の改訂は、これまでどおり本文に日付入りの見出しを立てる。数は 0 から数え直し、また 5 つを超えたら、増えた分を経緯ファイルの末尾へ足して本文を軽くする

経緯ファイルは ADR ではないので、`make adrs` は読まない。見出しを移すだけで経緯を捨てていないことは、書く人とレビューが確かめる (移した見出しの数が、本文から外した数と合う)。

## ADR の状態欄

方針が変わったら、状態欄がそれを示す。`採用 (日付)` に ` / ` で足す綴りは 3 つ:

| 綴り | 使うとき | 書く回数 |
| --- | --- | --- |
| `改訂あり (本文の「改訂 (日付)」見出し)` | 決定の理由は動かず、手段を差し替えた・足した | ADR ごとに 1 度だけ。一字一句この綴り |
| `一部置換 (→ ADR-00NN): <どの決定が>` | 決定の一部が別の ADR に取って代わられた | 置換されるたび |
| `置換済み (→ ADR-00NN)` | 全体が別の ADR に取って代わられた | 1 度 |

番号を増やすか本文を書き換えるかは、理由が生きているかで決まる。理由が動かず手段だけ変わったなら同じ ADR を改訂し、理由そのものが覆ったなら新しい ADR を立てて古い側を `置換` にする。

### 改訂の書き方

**改訂の正本は本文の日付入り見出しで、状態欄ではない** ([#1946](https://github.com/mokume-metal/mokume/issues/1946))。状態欄に改訂を 1 つずつ書き足す形は、同じ ADR を改訂する PR が並ぶと、どの 2 本も状態欄の同じ 1 行で必ず衝突した。見出しは改訂した決定のそばに立てるので、別々の決定を改訂する 2 本は衝突しない。

見出しの綴りは 2 通りで、どちらも日付を入れる (`make adrs` は「改訂」か「追補」と日付を両方持つ `##`〜`####` の見出しを改訂と数える):

```markdown
### 4. 承認は 1 件にする (2026-10-05 改訂)    ← 決定の見出しに併記する
#### 改訂 (2026-10-05) — 決定 4 の手段を差し替える    ← 決定の末尾に節を立てる
```

本文には「当初の決定は〜だった」と捨てたものを理由ごと残す (上の「現行の決定から読めるようにする」)。見出しが 5 つを超えたら、経緯を `history/` へ移す (上の「改訂が重なった ADR を軽くする」)。

状態欄は次のとおりに扱う:

- **初めて改訂するとき**: 状態欄の末尾に ` / 改訂あり (本文の「改訂 (日付)」見出し)` を足す。綴りは一字一句この形にする。並んだ 2 本が同じ文字を足すなら git は衝突させないが、1 字でも違えば衝突する
- **2 回目以降の改訂**: 状態欄に触れない。本文に見出しを立てるだけ
- **置換**: `一部置換`・`置換済み` は、いままでどおり状態欄に足す

例 — ADR-0021 は既に印を持っている。2 本の PR が同時に改訂し、X は決定 2 に、Y は決定 4 にそれぞれ `#### 改訂 (2026-10-05) — …` を足す。どちらも状態欄は変えないので、X が先に入っても Y は衝突せず merge queue に残る。改訂のまだ無い ADR を 2 本が同時に初めて改訂するときも、どちらも状態欄に同じ印を足すだけなので衝突しない。

2026-10-05 より前の改訂は、状態欄に ` / 改訂 (YYYY-MM-DD): <何を>` の並びとして残っている。消さずに凍結したもので、書き足さない。

改訂の一覧は見出しから引く (凍結した並びに無い、2026-10-05 以後の改訂もここに出る)。軽くした ADR は見出しが経緯ファイルにあるので、本文と経緯ファイルを並べて引く。次は `make adrs` が数える定義 (「改訂」か「追補」と日付を両方持つ見出し。日付は前でも後ろでもよい) の例で、ADR-0021 なら本文の 0 個と経緯の 14 個が出る:

```bash
grep -nE '^#{2,4} ' docs/decisions/0021-solid-space-and-frame-assembly.md docs/decisions/history/0021.md \
  | grep -E '改訂|追補' | grep -E '20[0-9]{2}-[0-9]{2}-[0-9]{2}'
```

### 機械が見るもの

`make adrs` (`scripts/check-adrs.sh`) が赤くするのは、改訂を抱えているのに状態欄に印が無いとき (日付入りの改訂の見出しがある、または凍結した ` / 改訂 (日付)` がある)、2026-10-05 より後の日付で状態欄に ` / 改訂 (日付)` を書き足したとき、本文の日付入りの改訂の見出しが 5 つを超えたとき (軽くし方は上の「改訂が重なった ADR を軽くする」)。本文の見出しの日付が状態欄にあるかは見ない。軽くした後の本文に案内の 1 行があるか、経緯ファイルが在るかも見ない。上書きされた側が `置換` を示しているかも見ないので、書く人とレビューが確かめる。
