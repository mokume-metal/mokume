# ADR-0037: ビルドの置き場は、版ごとに共有する

## 状態

採用 (2026-09-07)

## 文脈

`run` / `watch` は `swift build` に置き場を渡さないので、置き場は常にそのパッケージ直下の `.build` になる。**スケッチを 1 本作るたびに、mokume 本体を丸ごとビルドし直して 1 部屋ぶん持つ。**

実測 (Swift 6.3.3・公開版 v0.7.1 に依存する最小スケッチ)。新しいスケッチ 1 本の初回で **22.2s / 414MB**:

| | | |
| ---: | --- | --- |
| 149.5MB | `prebuilts` | swift-syntax のマクロ用 prebuilt バイナリ (展開後 123.6MB と zip 25.9MB を両方持つ) |
| 79.4MB | `ModuleCache` | macOS SDK のモジュール |
| 50.8MB | `repositories` + `checkouts` | swift-syntax の複製 |
| 39.6MB | `MokumeCore.build` | mokume 本体 |
| 32.9MB | `index` | 編集器のための索引 |
| 25.0MB | `MokumeMacros-tool` (+dSYM) | マクロを動かす実行ファイル |
| **14.0MB** | **スケッチ自身** | 実行ファイル 5.1 + dSYM 8.2 + `<target>.build` 0.34 |

**スケッチに固有なのは 3.6% で、残り 400MB はどのスケッチでも中身が同じ。** works で Processing の例を 157 パッケージへ組み替えたとき、全部で 65GB になった ([works#41](https://github.com/mokume-metal/works/pull/41)) が、払っているものは「brew で入れて普通にスケッチを作る人」と同じである。

置き場を 1 つにすると、2 本目以降は **2.5 秒 / +14MB** で済む。

### 測って分かった制約

1. **部分だけ共有する口は無い。** `--cache-path` を別に与えても置き場は 393MB のまま (キャッシュ側が持つのは圧縮された種で、置き場は展開後の写しを別に持つ)。内容で決まる = 取り違えの危険が無いもの (`prebuilts` / `ModuleCache`) だけを寄せる、という安全な形は選べない
2. **違う版を混ぜると往復が 5 倍遅くなる。** 違う版の mokume に依存するスケッチを同じ置き場で往復させると 1.6s → 7.3〜10.1s。[#784](https://github.com/mokume-metal/mokume/issues/784) が書いた「互いを作り直させ続ける」は、フラグの食い違いだけでなく**依存の版でも起きる**
3. **同名 product が実行ファイルを取り違える。** 別々のパッケージ 2 つ (どちらも product `hello`) を同じ置き場でビルドすると、a を指した `--show-bin-path` が返す先の実行ファイルに b の中身が入る。共有される名前空間は `debug/<product>` / `.dSYM` / `<パッケージ>_<ターゲット>.bundle` / `<ターゲット>.build/` / `Modules/<ターゲット>.swiftmodule`。**しかもこの壊れ方は黙っている**
4. **`.build` を共有の置き場へのシンボリックリンクにする案は使えない。** swift-frontend が `signal 11` で落ちる
5. **置き場を別のパスへ写すと硬い失敗になる。** `ModuleCache` の `.pcm` が自分のパスを焼き付けているため `missing required module 'SwiftShims'` で止まり、打ち直しても治らない
6. **置き場の計画ファイル (`build.db` / `debug.yaml` / `description.json`) が古いと、`swift build` は「Build complete!」と言って実行ファイルを 1 つも作らない**
7. **コンパイル結果の内容鍵付けキャッシュ (CAS) は使えない。** toolchain に `-cache-compile-job` / `-cas-path` は在るが、置き場が違うと 227 件すべて cache miss で CAS が 406MB に膨れるだけだった。鍵にコマンド行 (= 置き場のパス) が入るためで、パスを正規化する口 (`-scanner-prefix-map-paths` 等) は実験的である

### なぜ「口を足す」では足りないのか

[#1055](https://github.com/mokume-metal/mokume/issues/1055) は当初「`--scratch-path` を渡せるようにする (既定は変えない)」を提案していた。それは**知っている人だけが速くなり、しかもその人だけが制約 2 と 3 を踏む**形になる。払っているものが普通の利用者と同じなのだから、既定が効率的である必要がある ([ADR-0001](0001-founding-principles.md) 原則 1「『書いてから絵が出るまで』の時間を常に短く保つ」)。

そして**取り違えは共有の性質ではなく、走らせる先の決め方の問題**である。`debug/<product>` を組み立てて直接 exec しているのが原因で、その解決コードは道具が持っている。

## 決定

### 1. 置き場は `~/Library/Caches/mokume/build/<道具立て>/<固定>` に置く

派生物として消してよいものなので macOS の作法に乗せる。Time Machine の対象外で、`brew upgrade` でも消えないので、古い版に pin したスケッチの置き場が生き残る。

**鍵に道具立ての版を入れる。** 置き場の 55% (`ModuleCache` + `prebuilts`) は道具立ての産物で、食い違ったときの症状が作り直しではなく制約 5 の硬い失敗だからである。語は `swift --version` から `swiftlang-6.3.3.1.3` の形で取り出す — **ハッシュにしない**。切り分けの口が在処を名乗るので、人が版と突き合わせられる形にする。

**代償を引き受ける。** パスに利用者名が入るので、将来 brew が置き場の「種」を配るときは写して入れることになり、`ModuleCache` を捨てるぶん効き目が落ちる (1 本目 4.6s ではなく 8.4s + 400MB のコピー・[#1068](https://github.com/mokume-metal/mokume/issues/1068) に実測)。固定の絶対パス (brew の prefix 配下) なら全額買えるが、道具が package manager の管理下へ書き込むことになる。

根は `MOKUME_BUILD_DIR` で差し替えられる。**この綴りは ``StartupReads`` には載せない** — あの一覧は走らせたスケッチが起動の瞬間に読むもので、これは道具がビルドを始める瞬間に読むものである (`MOKUME_SIGN_IDENTITY` と同類)。

### 2. 共有できないときは、パッケージ直下へ落ちる

**専用の置き場を別に作らない。** 落ちた先が今までと同じなら、`rm -rf .build` も切り分けの口も孤児を拾う道具も、作法を 1 つも増やさずに済む。理由は 6 つで、どれも `.build` へ落ちる:

| 理由 | 名乗るか |
| --- | --- |
| パスで指した依存がある (mokume 自身の開発) | 黙る (開発の常道) |
| 配るものを組んでいる (`bundle`) | 黙る (選択ではなく設計) |
| まだ固定が読めない | 名乗る |
| パッケージの宣言が読めない | 名乗る |
| 道具立ての版が読めない | 名乗る |
| 同じ名前を別のパッケージが先に使っている | 名乗る |

**共有の常道では黙る。** 毎回言えば読まれるのをやめるので、言うのは「そうしなかったとき」だけにする。

**パスで指した依存を共有しないのは、鍵が固定なのに中身が動くからである。** worktree を `git checkout` で往復させれば、同じ鍵で別物になる。mokume 自身の開発ではソースからビルドするのが正しい。

### 3. 名前は、置き場に書く前に押さえる

置き場の `owners/<名前>` に持ち主のパスを 1 行だけ書く。押さえるのは**置き場で席が 1 つしか無い名前** — 宣言された executable product と全ターゲットの名前である (ひな形は package = product = target を同じ名前にするので、この集合が資材の包みと中間物まで覆う)。

- **ロックを持たない。** `O_CREAT | O_EXCL` は「無ければ作る」を 1 回の syscall で行うので、同時に走った 2 つのうち片方だけが成功する
- **1 本の台帳にしない。** 名前ごとに 1 ファイルにしておけば、壊れたとき 1 つの名前しか盲目にならない
- **読めない記録は「別人のもの」へ倒す。** 読めなかったことと書かれていないことを同じ顔にすると、書きかけを掴んだ側が先客を追い出す ([ADR-0018](0018-observation-and-control-surface.md) の流儀と同じ向き)
- 持ち主のディレクトリが消えていれば記録を解放して取り直す (作って消したスケッチの名前が、永久に共有を塞がないため)

### 4. 「ビルドが成功した」を信用しない

**作り直しの前に実行ファイルと `.dSYM` を消し、後で在ることを要求する。** 「在るか」ではなく「いま建ったか」を見る — 制約 6 のとき、存在を見るだけの検査は前の実行ファイルに騙され、**中身が別のスケッチのものを起動する。**

代償は再リンク 1 回で、見張りは毎回ソースが変わるので追加の費用は無い (無変更のまま `run` を打ち直したときだけ増える)。

**併せて、作り直しが通ったことと走らせるものが在ることを分ける。** かつては実行ファイルを解決できなかった回も成功として記録されており、症状は「保存した → 作り直したと出た → 絵が止まっている」で、記録のどこにも理由が出なかった ([#1066](https://github.com/mokume-metal/mokume/issues/1066))。

**ただし宣言が読めないことを、断る理由にはしない。** `Package.swift` を壊した状態から直していく途中は**まさに見張っていてほしい場面**である。名前が分からないときは作り直しの後に読み直す (その経路の置き場は必ずパッケージ直下なので、取り違えの危険はそこには無い)。

### 5. 置き場を指す計算は 1 箇所に置く

`workspace-state.json` と `checkouts/` を読む側 (面の仕様の在処・切り分けの口) は、`.build` を組み立ててはならない。組み立てていると、共有へ移ったスケッチで**黙って空振りする** — 「依存している mokume はこの面を持たない」という名乗りごと消える ([#791](https://github.com/mokume-metal/mokume/issues/791) / [#730](https://github.com/mokume-metal/mokume/issues/730) が写しで割れた歴史と同じ形)。

**読むだけの経路は「決める」のではなく「並べる」。** 置き場を決めるには宣言を読む必要があり (数百 ms のプロセス) 、道具立ての版を知るにはもう 1 プロセス要る。在る方を採る形にすれば、根を 1 段列挙するだけで済み、道具立てを入れ替えた後でも前の置き場を見つけられる。

### 6. 判断は 1 回だけ行い、抱き合わせた値で持ち回る

構成と置き場と product を 1 つの値にして渡す。**片方だけ渡せる形にしない** — 構成でそれを踏んだのが [#680](https://github.com/mokume-metal/mokume/issues/680) で、置き場でも同じことが起きる (作り直しは共有・解決はパッケージ直下、という組み合わせになる)。

### 7. 掃除の口は足さない

共有を既定にすると `rm -rf .build` では消えないものが生まれる。**切り分けの口が在処と鍵の数と合計の大きさを名乗る**ようにして、掃除は `rm -rf` に任せる ([ADR-0008](0008-mechanism-needs-demonstrated-harm.md) — 実害が出てから足す)。

## 影響

- 2 本目以降のスケッチが **22.2s / +414MB → 2.5s / +14MB** になる。works の 157 パッケージなら 65GB → 2.6GB
- **`rm -rf .build` は「共有をやめる」操作ではなくなる。** 共有の置き場は残るので、`mokume doctor` が在処を名乗る
- **同時に 2 本 `watch` すると、作り直しが SwiftPM のロックで直列になる。** 同じ版どおしなら 1 回 2.5 秒なので実用の範囲だが、今までは並行だった
- 同名のスケッチのうち**先に走ったほうだけ**が共有の利得を得る。後から来たほうは 414MB を払い、そう名乗る
- `bundle` は共有を使わない。束ねる側は実行ファイルの隣に並んだ包みを全部入れる作りなので、共有すると**他人の資材が配る包みへ入る**
- 決定 1 の代償として、brew が種を配る形 ([#1068](https://github.com/mokume-metal/mokume/issues/1068)) の効き目は落ちる。全額を買いたくなったら根の位置を再考する — 根を決める計算は 1 箇所にあるので、差し替えは 1 行である
- **この決定は 400MB を「版につき 1 部屋」に畳むだけで、無くしはしない。** うち 225MB は `@Param` のために全スケッチが建てる swift-syntax 一式で、そちらは [#1069](https://github.com/mokume-metal/mokume/issues/1069) が別に問う
