# ADR-0009: OS フロアとツールチェーンを macOS 26 / Metal 4 / Swift 6 に一本化する

## 状態

採用 (2026-08-27)

## 文脈

[ADR-0001](0001-founding-principles.md) 原則 5 は対象プラットフォームの方針だけを定め、具体の世代は個別 ADR に委ねた。

> **macOS / Apple Silicon 専用・最新世代への一本化・外部依存は最小** — 対象プラットフォームを絞り、Swift・Metal は単一の最新世代に一本化する (**採用する世代の具体は個別 ADR で確定する**)。旧世代との並走サポートは持たず、互換ビルドを検証する CI も持たない。

本 ADR がその具体を確定する。決めるのは 4 つ — OS フロア・GPU API 世代・Swift 言語モード・開発とビルドに使う Xcode である。

### なぜ最初のコードより先に決めるのか

この 4 つは `Package.swift` の宣言と、以後書くすべてのソースの前提になる。**引き上げは後からでもできるが、下げることはできない**。そして低いフロアで始めると、その間に書いたコードは低い世代の語彙で書かれるため、後の引き上げは「宣言を変える作業」ではなく**全域の書き換え**になる。特に並行性と GPU コマンド構造は、コードの構造そのものに現れるため後から差し替えられない。

### 利用者がいない今だけの条件

現時点でこのライブラリの利用者はいない。互換性の負債がゼロである状態は一度きりで、後から作り直せない。**後付けでは最も高くつく 2 つの移行 — 言語レベルの並行性検査 (strict concurrency) への適合と、GPU コマンド構造の刷新 — を、いまなら差額ゼロで採れる。**

### プラットフォームの動向 (2026-08 時点)

- macOS 26 (Tahoe) が現行世代。Metal 4 と Swift 6.2 以降の並行性機構 (`defaultIsolation` など) はこの世代で揃う
- macOS 27 が 2026 年後半にリリース予定で、**初の Apple Silicon 専用 macOS** となる。プラットフォーム側が原則 5 の前提 (Apple Silicon 専用) に追いつく形になる
- したがって 1.0 到達時点で macOS 26 は n−1 世代になり、「macOS 26 以上」は当時のフロアとしてむしろ保守的な位置に落ち着く

### 並走を持つと何が生まれるか

複数世代を同時にサポートすると、次のクラスの仕事が恒常的に発生する。

- 旧ツールチェーンでビルドが通ることを確認する CI ジョブ (新しい SDK にしか無いシンボルの混入は、新しい環境では検出できない)
- 実行時・コンパイル時の世代分岐と、分岐それぞれの検証
- 新機能を採る前に「旧世代でどう degrade させるか」を毎回設計する負担

原則 5 は既にこれを持たないと宣言している。本 ADR はその宣言を具体的な数値に落とすだけであり、新しい方針を導入するものではない。

## 決定

### 1. OS フロアは macOS 26 (Tahoe)・Apple Silicon 専用

`Package.swift` の `platforms` は macOS 26 を最小とする。Intel Mac は対象にしない。

### 2. GPU API は Metal 4 世代のみ

Metal 4 の機構 (新しいコマンド構造・argument table・シェーダコンパイルの高速化・MetalFX・ML 統合) を前提にしてよい。**旧世代の API へのフォールバック経路を持たない** — 分岐を持てば、分岐した先の検証も持つことになる。

### 3. Swift 6 言語モード・`swift-tools-version` は 6.x

Swift 6 言語モードを day 1 から使う。言語レベルの並行性検査は警告ではなく**エラー**として働く状態で開発を始める。escape hatch で黙らせながら書き進める余地を最初から与えない。

### 4. Xcode 26 以上を開発と CI の前提とする

CI は単一の Xcode で回し、**旧ツールチェーンでの互換ビルドを検証するジョブを持たない**。検査の入口が `make ci-check` 1 つであること (原則 8) と整合する。

### 5. フロアの引き上げは自動では行わない

macOS 27 が出てもフロアは自動追随しない。引き上げは本 ADR の改訂として、そのとき判断する。**引き上げれば既存の利用者が置き去りになる**以上、判断は明示的な記録を伴うべきである。

## 影響

- `Package.swift` は macOS 26 を宣言し、以後のソースは `#available` による世代分岐を持たない。分岐が必要に見えたら、それはこの ADR の範囲外の機能を使おうとしている合図になる
- Metal 4 を前提にできるため、ビュー層 ([#135](https://github.com/mokume-metal/mokume/issues/135))・ML の位置づけ ([#137](https://github.com/mokume-metal/mokume/issues/137))・MetalFX ([#138](https://github.com/mokume-metal/mokume/issues/138)) の各 ADR は、フォールバック設計を検討対象から外してよい
- 並行性規範 ([#133](https://github.com/mokume-metal/mokume/issues/133)) は Swift 6 言語モードが有効な前提で書ける。「移行期の緩和措置」を設計に含めない
- CI は単一ジョブで足り、互換ビルドの検証というジョブのクラスが存在しない
- macOS 26 未満の環境では利用できない。これは意図した制約であり、緩和は本 ADR の改訂を要する
- 自動検証を担う機材 (将来の self-hosted ランナーを含む) も macOS 26 以上を要する
- 決定 5 により、OS の新世代が出るたびに「上げるか」の判断が発生する。判断を省略して追随することはしない
