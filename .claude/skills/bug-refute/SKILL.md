# 反証役を起こす

規律は 1 行である — **Bug を閉じる PR には、プランと完了条件を渡されない独立した反証役の
指摘と、それへの応えを載せる。** 手順はここで完結する (理由と退けた案: ADR-0040 決定 4)。

独立させるのは、棚卸し・プラン・実装・検証を同じエージェントが担うと、**完了条件の範囲が
そのまま調べる範囲の上限になる**からである。#1659 で直近の fix PR を読み直したところ、原因の
特定と再現テストはよくできていたが、兄弟の口を探さず、同じ根のバグが後から 1 件ずつ出ていた。
レビューコメントは 0 件だった。プランを読んだ目は、プランが見た範囲しか見ない。

`scripts/review-gate.sh` が見るのは、閉じる Issue に Bug が含まれる PR の本文に、空でない
「反証」の節があることだけである (#1662)。指摘の質も応えの妥当性も見ない。

## 1. いつ起こすか

直しと再現テストが揃い、触った範囲の段 (`make <段>`) を通した後、PR を出す前 (Draft でもよい)。
差分が固まる前に起こすと、指摘が古い差分に向く。

**1 回でよい。** 指摘を受けて差分が大きく変わった (別の場所へ直しを広げた) ときだけ起こし直す。
指摘が出なくなるまで起こし直すことはしない — 通るまで引き直すのは反証ではない。

## 2. 材料を揃える

渡すのは **2 つだけ**:

| 渡すもの | 取り方 |
| --- | --- |
| Issue の症状 (本文のうち、事象と再現の部分) | `gh issue view <番号> -R mokume-metal/mokume --json title,body` |
| 修正の差分 | `git diff origin/main...HEAD` (反証役に作業ツリーの中で打たせる) |

**渡さないもの**: プラン (Issue / PR のコメント)・完了条件の節・PR 本文・自分の推測した原因。
渡すと反証役が同じ範囲に縛られ、独立した目でなくなる。Issue 本文から「完了条件」の節と、
原因の推測を書いた段落を切り落としてから貼る。症状の書き手が起票者でもエージェントでも同じ。

## 3. 起こす

Agent ツールで、書き込みをしないサブエージェント (`general-purpose`、高性能モデル) を 1 本起こす。
プロンプトは次の形をそのまま使い、`<…>` だけを埋める。

Codex では、会話履歴を継承しないサブエージェント (`spawn_agent` の `fork_turns: "none"`)
に同じ材料を渡す。ツール名が異なる環境でも、履歴を渡さず読み取りだけに限定する。
独立したサブエージェントを起こせない環境では、同じ材料だけを渡す別セッションか人の
反証を用意する。自分の読み直しを独立した反証として記録しない。

```text
あなたは mokume (macOS 専用の Swift + Metal のクリエイティブコーディング環境) のバグ修正に
対する反証役です。修正した本人とは独立に、この直しの穴を探してください。

渡すのは 2 つだけです。修正者のプランと完了条件は、わざと渡していません — それを読むと、
修正者が見た範囲しか見なくなるからです。

## 症状 (Issue #<番号> の本文のうち、事象と再現だけ)

<貼る>

## 差分

作業ツリー <worktree の絶対パス> で `git diff origin/main...HEAD` を打って読んでください。
コードベース全体は自由に読んで構いません。

## 探すもの

1. 兄弟の口: 同じ原因・同じ形 (同じ前提・同じ呼び方・同じ計算・同じ既定値) を持つ場所で、
   この差分が直していないもの。探した grep / rg の式を、当たらなかったものも含めて全部書く
2. 壊しうるもの: 変更した関数・型・既定値を使う呼び出し元や経路で、この差分によって振る舞いが
   変わってしまうもの
3. 根か症状か: この直しは約束 (不変条件・契約) を破った根を直しているか、症状が出る 1 箇所を
   塞いでいるだけか。症状なら、根はどこか

## 守ること

- 読むだけ。ファイルを書き換えない・コミットしない・gh を使わない (Issue のコメントと PR
  本文にはプランが書かれていて、読むと独立でなくなる)
- 指摘ごとに根拠の file:line を付ける。file:line を示せない推測は指摘にしない
- 見つからなかった項目は「見つからなかった」と書き、探した式を添える

## 返す形

| # | 種類 (兄弟 / 壊しうる / 症状) | 指摘 | 根拠 (file:line) |

表の後に、探した式の一覧を付ける。
```

## 4. 応える

指摘 1 件ごとに、応えは **3 通りのどれか**:

| 応え | いつ | 書き方 |
| --- | --- | --- |
| 直した | この PR で直した | `直した` (コミットの短い SHA を添えてよい) |
| 起票した | この PR の説明で筋が通らない | `起票した #N` |
| 当たらない | 指摘が誤り・既に守られている | `当たらない: <理由>` (理由には読んで確かめられる根拠 — file:line・検査名 — を付ける) |

**同じ根の兄弟は、この PR で直すのが既定である** (理由: ADR-0040)。「起票した」に回してよいのは、
AGENTS.md の「作業中に踏んだ問題」の表で 1 行目 (その PR の説明で筋が通る) に入らないものだけで、
起票の行き先もその表に従う:

- 完了条件を自分で書ける → 起票し、完了条件を本文に書いて `verify: triaged` まで付ける
- 完了条件を書けない (約束を決める・変える判断が要る) → ラベルなしで置き、メンテナの判断を待つ

直した兄弟には再現テストも広げる。検査が範囲全体を回っていなければ、同じ根は次の 1 件として戻る。

## 5. PR 本文へ貼る

`.github/pull_request_template.md` の「## 反証」節に、次の形で貼る。

```markdown
## 反証

反証役: サブエージェント 1 本 (Issue の症状と差分だけを渡した。プラン・完了条件は渡していない)

| # | 種類 | 指摘 | 根拠 | 応え |
| --- | --- | --- | --- | --- |
| 1 | 兄弟 | 同じ形の口が `Foo.draw` にもある | Sources/MokumeCore/Foo.swift:42 | 直した (abc1234) |
| 2 | 壊しうる | `Bar.init` の既定値を読む呼び出し元がある | Sources/MokumeCore/Bar.swift:17 | 起票した #N |
| 3 | 症状 | 根は `Baz` の丸めで、ここは症状を塞いでいる | Sources/MokumeCore/Baz.swift:88 | 当たらない: 丸めは約束の範囲外で、Baz.swift:90 が境界を保証している |

探した式: `rg -n '<式>' Sources/` ほか (反証役の返答から写す)
```

指摘が 1 件も無ければ、表の代わりに「指摘なし」と探した式を書く。それでも節は空ではない。

**当たらない指摘も消さずに残す。** 採られた率 (指摘のうち直した・起票したの割合) がほぼ 0 なら
反証役を畳むと決めてある (理由: ADR-0040 決定 4)。都合の悪い行を落とすと、畳むかどうかの
判断が狂う (数え直しは #1663)。

## しないこと

- **自分で反証役を兼ねない。** プランを書いた目で読み直しても、プランの範囲の外は見えない
- **プラン・完了条件・PR 本文を渡さない。** 「文脈があったほうが的確になる」は、そのまま
  同じ範囲に縛る理由である
- **指摘を反証役に直させない。** 反証役は読むだけで、応えるのは PR の書き手である
